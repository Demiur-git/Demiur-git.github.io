[相册](/gallery/)首页会把每个相册呈现为阅览桌上的影像册。站长需要准备两部分：真实照片，以及 `src/config/galleryConfig.ts` 中的相册资料。只改显示名称不会自动生成照片。

## 第一步：确定相册 ID 与目录

以 `autumn-walk` 为教学示例。建议 ID 使用英文小写字母、数字和连字符，保持唯一，不包含斜杠或 `..`。

在 `public/gallery/` 下创建同名目录，将有权公开的照片放进去：

```text
public/
  gallery/
    autumn-walk/
      cover.webp
      01-path.webp
      02-leaves.webp
      03-window.webp
```

这些名称是示例，不是网站已有照片。扫描器读取这一层目录中的 JPG、JPEG、PNG、WebP、AVIF、GIF，不递归扫描子文件夹。建议先压缩大照片，手机不必为预览下载未经处理的巨型原图。

## 第二步：填写相册资料

打开 `src/config/galleryConfig.ts`，在 `galleryConfig.albums` 中追加对象。保留其他相册，不要把整个数组替换成示例：

```ts
{
  id: "autumn-walk",
  name: "秋日散步",
  description: "沿着小路收集的一些光影。",
  date: "2026-09-27",
  location: "公园",
  tags: ["秋天", "散步"],
}
```

`id` 与 `name` 必填，其余说明字段可省略。对象之间要用逗号分隔。保存并重建后，这本相册的网址是 `/gallery/autumn-walk/`；搜索读取名称、简介等信息，标签来自 `tags`。

## 封面与照片顺序

封面优先级是：配置中的 `cover` → 目录里的 `cover.*` → 第一张照片。手动指定时写浏览器路径，不含 `public`：

```ts
cover: "/gallery/autumn-walk/02-leaves.webp",
```

本地照片按文件名排序，`cover.*` 优先放到前面。用 `01-`、`02-` 等前缀可控制顺序。封面文件也属于扫描结果，会出现在相册照片中；手动封面地址则不会凭空新增一张内部照片。

桌面端悬停或键盘聚焦时，最多两张封面之外的真实照片从影像册中抽出；不足两张按实际数量展示。手机简介常驻，点击直接进入详情。只有一张图或没有照片时，不会复制出虚假的预览。

## 可选：使用远程照片

扫描器支持同一相册目录内的 `urls.txt`，每行一个可公开读取的图片 URL，空行与 `#` 注释会忽略：

```text
# 将这里的示例地址换成真实图片地址
https://images.example.com/autumn/01.webp
https://images.example.com/autumn/02.webp
```

远程照片接在本地照片后，按文件中行的顺序排列。仍需创建相册目录并填写 `albums`。远程托管要允许浏览器加载，地址必须稳定；外链失效、防盗链或 HTTP/HTTPS 混用都会影响展示。

## 修改、删除与密码提示

改简介、标签、日期通常不需要更换 ID。替换照片时保留想继续使用的文件名，并核对 `cover` 是否仍存在。

删除相册时，先从 `albums` 移除对应对象。若不再公开其照片，也要移除对应的公共资源或远程文件；仅移除入口并不会让 `public/` 中的图片无法通过直接地址访问。重新命名 ID 则会改变详情页链接，需要同步移动目录和修改相关引用。

相册字段还支持 `password` 与 `passwordHint`。加密相册不会在首页抽出内部照片，但封面、公开静态文件与公开仓库不是私密存储：不要用该功能发布敏感照片，也不要把真正的账号密码写进配置。

## 发布前检查

1. 目录名与相册 `id` 完全一致，文件大小写与封面路径正确。
2. 首页显示真实封面，简介与标签可搜索，详情照片能打开。
3. 桌面悬停、键盘聚焦和手机点击均正常；亮暗模式下介绍文字可读。
4. 照片无不希望公开的 EXIF 定位、证件、人物隐私等信息。
5. 构建通过，照片与配置一起发布；只提交配置不会把未上传的图片带上网站。
